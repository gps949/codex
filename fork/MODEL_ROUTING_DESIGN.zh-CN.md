# 自动选模型：设计方案

[English](MODEL_ROUTING_DESIGN.md) · [决策服务](DECISION_MODELS.zh-CN.md)

**状态：已完成设计研究，尚未实现为可用功能。** 现有决策辅助负责工具排序和可选的技能建议，不会自动改变 Codex 模型或思考程度。下面是拟议界面，不是本版已经支持的配置项。

Jev/Clef 可以将任务分类，再由本地程序选择模型。TypeSafe 官方提供了“分类意图与复杂度，再分配处理模型”的示例；Cloudflare 模型卡包含路由实验。这些资料支持技术可行性，但不能证明本 fork 的开发任务和订阅额度已经获得实测收益。[TypeSafe 路由](https://docs.typesafe.ai/patterns/intent-routing)、[Cloudflare 模型卡](https://huggingface.co/Cloudflare/clef)、[Workers AI 接口](https://developers.cloudflare.com/workers-ai/models/clef/)。

## 界面与策略

管理器增加独立的“自动选模型”卡片，设置如下：

| 设置     | 建议行为                                                   |
| -------- | ---------------------------------------------------------- |
| 模式     | 默认关闭；“仅预览”展示拟议选择；“自动”才应用合法选择。     |
| 范围     | 主任务、子代理分别开关，先从子代理评估效果。               |
| 倾向     | 整数 **0–100**：0 更重续航，50 平衡，100 更重能力。        |
| 决策来源 | 本地规则，或已接入的 **Jev / Clef**；二选一即可。          |
| 候选限制 | 从当前提供商的允许模型中选择，可进一步限制模型和思考档位。 |
| 失败回退 | 保留当前模型及思考程度；本地规则回退需要单独开启。         |

这个数值表示可用候选之间的取舍，不代表额度倍数。即便是 0，复杂任务也必须满足能力下限；即便是 100，简单任务也不必使用最强模型或最高档位。Ultra 会改变委派行为，因此滑杆不能隐式开启 Ultra 或扩大代理权限。

手动模型、手动思考程度、固定角色、管理员要求和明确的子代理参数优先。用户主动选择“自动”后才解除手动固定。自动选模型与工具排序、技能建议、付费推理兜底、自动兑券各自独立，不能互相悄悄开启。

## 选择过程

1. 本地构造当前提供商、当前认证目录允许的候选，过滤输入模态、上下文容量、工具协议、思考档位、服务等级和访问限制。未知模型保持已有选择，不通过名称猜测价格或能力。
2. 决策服务仅接收任务描述和有限决策信息，不接收完整历史、源码、工具结果、账号身份或额度记录。分类任务类型、推理深度、不确定性和正确性要求；本地程序负责权重、能力下限与切换成本。
3. 低置信度、判断冲突、未知选项、格式错误、版本不符、超时、取消、无令牌、网络禁止或模型目录变化，都保留当前选择，不自动重复付费分类请求。
4. 在新任务开始或子代理创建时选择一次，经 Codex 现有校验入口应用；任务内的追加指导、重试、继续和恢复保持稳定。宿主要求完整历史继承时继续继承，不重写历史或为了路由强制重建模型客户端。

复用已有决策传输的超时、并发和载荷限制，新增独立的路由范围及数据发送同意。缓存绑定策略、偏好、固定参数、目录版本、服务与凭据、任务边界；短期请求缓存与任务内固定选择是不同概念。

## 续航不能只看单次请求

能力不足可能带来返工或更多子代理；更小上下文可能触发压缩；换模型也可能影响缓存和专属指令。因此应优化“完成整个任务的总工作量”，不能每次请求都挑看似最省的模型。API 价格不能直接换算成订阅窗口消耗。没有对应数据时，界面应显示“暂无用量估算”，而不是虚构节省百分比。

## 状态与验收

显示实际模型、思考档位、来源、倾向及简短理由，例如“范围明确的小修改”“歧义较高”“上下文限制”“保留手动选择”。区分“已保存”“建议选择”“已应用”，无需生成长篇解释。

分阶段实现：本地候选策略及说明；模拟后端的类型化分类；主动开启的子代理路由；主任务入口与各端管理。评估成功率、返工、总 token、缓存、决策开销、任务耗时和真实订阅额度；API 费用单独统计。本方案尚未使用真实提供商进行效果对照。
